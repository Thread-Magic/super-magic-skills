# Morning Briefing

**When to use:** Start of the day or shift — a dispatcher or team lead wants one clean, scannable picture of every open ticket across the desk's support tiers, the monitoring/alert noise stripped out, and the day's priorities called out.

**Run it:** across all open tickets on your support boards, on demand each morning.

## Prompt

```
Produce a morning briefing of open work across the desk's support boards — filtered, grouped,
flagged, and ready to act on. This is a report to read on screen, so format it richly in markdown.

OUTPUT DISCIPLINE
The very first character of your reply must be the "🌅 Morning Briefing" header. No preamble, no
"I'll run the briefing", no "fetching data" — nothing before it.

WHAT TO PULL
- Open tickets on your first-line (Tier 1) support board and your second-line (Tier 2) support
  board. If it isn't obvious which boards are first- and second-line, list the boards and ask me
  which to use before running — don't guess.
- Tickets in a scheduled status on each board.
Search each board with a generous limit, and if a search may have hit its cap, say so rather than
implying you saw everything.

FILTER OUT THE NOISE (first-line board only)
Exclude the tickets that aren't real human work — the alert/automation firehose:
- Alerts, monitoring, security-automation, or rules-engine tickets (by ticket type or the board
  they came in on).
- Tickets whose sender is a system or no-reply address (noreply@, no-reply@, or a monitoring/RMM
  service address).
- Tickets clearly generated by an automated tool — RMM, monitoring, security, or backup platforms.
- "Unknown" client or contact, and anything flagged for deletion.
Keep the genuine human-raised work: hardware, software, printing, installs, onboarding/offboarding,
access requests, line-of-business apps, email, and network issues from a real contact. When you're
unsure whether something is human work, keep it.
Second-line board: include ALL open tickets — no exclusions.

READ MESSAGES ONLY WHERE IT ADDS VALUE
- On Hold / waiting-on-vendor / waiting-on-parts tickets: read the latest internal note and use it
  to write the Next Steps line.
- Customer-updated tickets: read the latest customer message and use it for the Customer Update line.
- Scheduled tickets: read the latest internal note for Next Steps.
- Everything else: use the data you already have — don't open messages you don't need.

STALENESS, SLA, AND FLAGS (per ticket)
- Last updated: how long ago it last moved — "5h ago", "1d ago", "3d ago".
- SLA: 🔴 if the SLA is breached, 🟠 if it's within about 2 hours of breaching. If there's no SLA
  timer to read, fall back on age by priority — Critical/High: 🟠 at 4h+, 🔴 at 8h+; Medium: 🟠 at
  2d+, 🔴 at 4d+; Low: 🟠 at 5d+.
- Flags, shown only when true: 🚨 unassigned (no assignee at all), ⚠️ created 3+ days ago,
  🔴 SLA breached, 🟠 SLA warning. A ticket with an owner and under 3 days old gets no flags.

OUTPUT FORMAT
Open with:

### 🌅 Morning Briefing — [today's date]

#### 📅 Scheduled Today
List the tickets scheduled for today. If none: "Nothing scheduled in the planner today."

Then one section per board — first-line, then second-line — each clearly headed and grouped into
these five buckets, in this order:
- 🚨 Needs Attention — unassigned OR High/Critical priority
- 🟡 Waiting on Customer
- 🔵 On Hold — on hold, or waiting on a vendor or parts
- 🟢 In Progress / Completed — in progress, acknowledged, customer-updated, or completed
- 📅 Scheduled (future) — scheduled for a future date, not today (never fold these into In Progress)

Lead the first-line section with one line: "After filtering out alerts, monitoring, automation,
no-reply senders, unknown clients, and flagged-for-deletion tickets, N human tickets remain."

Render each ticket as a small block: a one-row table of Ticket# (carrying its flags, linked to the
ticket) · Client · Status · Assignee · Last Updated, then on its own line a 6-10 word summary
prefixed with "↳". Add a bold "Customer Update:" line (8-10 words drawn from the last customer
message) only on customer-updated tickets, and a bold "📌 Next Steps:" line only on on-hold and
scheduled tickets. Keep a blank line between each element and between ticket blocks so it stays easy
to scan.

Close with:

#### 🔢 Quick Stats
A table with one row per board: Open · Needs Attention · Waiting Customer · On Hold · Scheduled ·
🔴 SLA Breach · 🟠 SLA Warning.

#### Key actions for today
The handful of most important follow-ups, as bullets. Each bullet starts with 📞 (a follow-up or
call) or 🚨 (an unassigned ticket that needs an owner), names the responsible tech in bold, says in
a few words what needs to happen, and ends with the linked ticket. Focus on unassigned tickets,
High/Critical priority, customers waiting on a tech reply, and time-sensitive items — appointments,
out-of-office returns, vendor follow-ups.

Link each ticket to its own URL — never invent a link or a domain. Report only what the tickets
actually show; don't inflate, and don't fabricate clients, assignees, or updates.
```
